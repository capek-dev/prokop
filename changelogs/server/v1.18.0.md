### Added

- **Claude Code sessions**: Run a session on the installed `claude` CLI with its existing login. Pick the model and effort in the session picker. Claude's built-in tools, including Agent subagents, run through Prokop permission checks, and subagent activity is saved in linked sessions. Sessions support image uploads, Stop, native `/goal`, manual compaction, fork, and Edit and Undo. Workspace memory, agent memory, session search, and agent skill management are available as tools, and the selected agent's prompt, home, and memory are added to Claude's system prompt.

- **Codex CLI sessions**: Run a session on the installed `codex` CLI (0.156.0 or newer). Command and file-change approvals go through Prokop asks, and Codex subagents are saved as linked, read-only timelines. Sessions support image uploads, native Goals with a token budget, manual compaction, fork, Edit, and Undo. Workspace memory, agent memory, session search, and agent skill management are available as tools, and the selected agent's instructions and memory are supplied on every thread start and resume.

- **One model picker for every harness**: Choose Prokop, Codex, or Claude models from one picker with a harness rail. The first message locks a session's harness; model and effort stay changeable within it. Agents can pin a model from any harness, and a plain **New Session** follows the default agent's pin.

- **Harness settings**: **Settings → Server → Harnesses** shows each CLI's installed version and lets you disable Codex CLI or Claude CLI for new sessions and scheduled jobs. Existing sessions keep running.

- **Plan usage**: **Settings → Usage** shows the 5-hour, weekly, and per-model limits of the Claude CLI and Codex CLI logins, with reset times. API-key logins show a note instead of bars.

- **Agents out of the box**: Every primary agent gets memory, skills, learning, and a home workspace automatically, with no promote step. **Settings → Agents** manages each agent's capabilities, learning, and home `USER.md` and `MEMORY.md`.

- **Learning on any harness**: A learner pinned to a Codex or Claude model runs its reviews on that harness. These reviews cannot be undone from history.

- **Branches history**: History draws a commit rail that marks commits to push (green), commits to pull (amber), and shared commits, with branch chips, the upstream position, and day headings. The sync line reads "3 to push", "1 to pull", "Diverged", or "Up to date", and its counts open Push and Pull. "Fetched 12m ago" sits next to a fetch button, and counts dim after an hour without a fetch. The branch picker gains a Recent group.

- **Notifications for Claude and Codex**: Finished replies and permission asks in Claude Code and Codex CLI sessions now send web-push notifications, following the same rules as Prokop sessions.

- **Session titles for every harness**: Claude Code and Codex CLI sessions get generated titles after a turn, like Prokop sessions.

- **Diagnostics**: Server logs record each Claude and Codex turn's start, finish, or failure, with the failure phase and the end of the CLI's stderr. Setting `PROKOPAI_PERF_DIAGNOSTICS=true` also logs event-loop stalls with the requests and events that ran during them. Prompt and reply content is never logged.

### Changed

- **Permission modes**: Standard, Extended, and Full replace the five-level auto-approve setting for sessions, workspaces, and scheduled jobs. Commands and file operations ask only for a concrete concern: outside the workspace, secrets, destructive, or running unknown code. Asks show that concern and its evidence. Catastrophic commands such as `rm -rf /*` ask in every mode, and all three harnesses apply the same rules. Paths in the agent's own directory and the workspace's additional paths no longer ask as outside the workspace.

- **Live updates without polling**: Git status, the file tree, scheduled jobs, session lists, and running indicators are pushed by the server to every open client, including changes made by subagents and other sessions. The Files refresh button recomputes instead of re-reading a cache. Commits typed in a terminal and edits from an external editor appear on window focus or the next tool call.

- **Faster Claude and Codex sessions**: The server no longer stalls while CLI sessions stream, the model picker no longer waits on a CLI start after the first load, and streamed text finishes each part before the next one appears.

- **Built-in tools**: The catalog drops from 24 to 18 tools. `edit`, `edit-range`, and `multiedit` merge into one `edit` tool, `todowrite` and `todoread` merge into `todo`, and `ls`, `apply-patch`, and `git-worktree` are removed.

- **Tool rows**: Claude and Codex tool rows use the same names and views as Prokop tools: shell output, diffs, code, file lists, and todo lists. Long tool output scrolls inside its row on screens 640px and wider.

- **Settings layout**: Settings group into Preferences, Server, and Prokop. Providers & Models becomes one card per provider with its connection and models. The agent editor collapses its sections, Auto-Approve merges into Permissions, the Files tab moves into Appearance, and Account is renamed System. Memory, Skills, and Session Search merge into one Agent Tools panel, and session search is always on.

- **Model variants**: A Prokop session on a model with variants always has a concrete variant; the "Default" option is gone. **Providers & Models** sets the default variant for the default model.

- **Terminal panel**: The terminal opens and closes only from the app header. Running terminals keep running while it is hidden.

- **Agents naming**: "Preconfigs" are called "agents" throughout the app.

### Fixed

- **Claude and Codex sessions recover from failures**: A usage limit, API error, Stop, or failed Edit or Undo no longer leaves a session that refuses every message. Error messages include the CLI's own text, such as the limit reset time, and say how to recover.

- **New sessions open themselves**: Creating a session no longer opens a subagent session or a session created on another device at the same moment.

- **Claude model names**: Claude Code 2.1 model pickers show model names again instead of their descriptions.

- **Claude turns and transcripts**: Turns no longer fail when Claude Code is open in another terminal, and text written after a tool call appears after that tool's row.

- **Agent learning for Claude and Codex**: Agent learning now picks up Claude and Codex sessions and actually runs reviews on those harnesses. Learning history links open their sessions.

- **Tool row display**: Claude Read rows no longer show the file as an overwrite, and Codex shell rows without output no longer show `""`.

### Removed

- **Provider editing**: Providers can no longer be created, renamed, or deleted in the app or through the API (including the SDK `createProvider`, `updateProvider`, and `deleteProvider` methods). Providers come from `~/.prokopai/models.json` or a registry Sync. Model editing is unchanged.

- **OpenAI API and plain Z.AI providers**: The catalog keeps DeepSeek, MiniMax, Z.AI (Coding Plan), and Codex. Existing OpenAI entries in `models.json` show as an unsupported provider that can be deleted.

- **Model cost tiers**: Budget, standard, and premium badges and the Tier field are gone. Existing `models.json` files still load.

- **Capability risk levels**: Memory, Skills, and Session Search are on or off, with no per-capability risk setting.

- **Agent scheduler tool and Workflow capability**: Agents can no longer schedule jobs themselves, and the Workflow and Scheduling workspace capabilities are removed. Scheduling jobs from the app is unchanged.

### Operational notes

- **One-time permission migration**: On first start, saved permission grants are cleared and existing settings map to the new modes: high to Full, medium to Extended, everything else to Standard.

- **CLI requirements**: Claude Code sessions need Claude CLI 2.1.259 or newer, and Codex CLI sessions need Codex CLI 0.156.0 or newer, each already logged in on the server host. CLI sessions accept image attachments only.

- **CLI upgrades**: Claude Code and Codex CLI sessions are bound to the CLI version that started them. After the CLI updates, existing sessions refuse new messages. For a Claude session, editing its first message starts it over.
