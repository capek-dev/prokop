### Changed

- Allow manual compaction of idle Codex CLI sessions through the existing Compact action. Wait for a completed native compaction turn before reporting success; block further turns if the upstream outcome cannot be confirmed. Broadcast compaction state, retain a dated completion indicator and transcript divider, and use fresh Codex usage instead of displaying the pre-compaction context percentage.

- Persist Codex-spawned child threads as linked, read-only subagent timelines. Route child text and tool events to their own session, keep the shared app-server connection open after parent completion when children exist, and allow a follow-up parent turn on that connection. Permit child hooks and native command approvals in real subdirectories of the selected root while denying paths outside it. Send child approval prompts to the parent controller while retaining their child origin in live and resumed asks, preserve child-owned pending requests and once-only grants, and resolve parent-scoped hook or native approval calls only when their turn ID uniquely matches a live child. Keep parent running and approval indicators visible while viewing a child and show the same approval to the parent controller from either timeline. Name denial categories without exposing hook payloads. Instruct the parent to wait for a requested child result before ending its turn; completed parent turns do not auto-resume. Show Codex agent wait status instead of raw tool JSON, including previously saved rows.

- Accept Codex CLI 0.156.0 and newer instead of requiring the 0.156.x series.
- List selected-agent home skill metadata and `SKILL.md` paths in Codex developer instructions, subject to the preconfig allowlist and workspace-skill precedence. Route only `agent_skill_manage` through Čapek's skill manager for selected agents; workspace skill management and native Codex skill discovery remain unchanged. Show skill lists and mutation status in Codex tool rows instead of raw JSON, including previously saved rows, and require an explicit raw-data action for structured previews.

- Expand saved slash prompts in Codex CLI chat messages, including arguments and uploaded images. Leave goal conditions and unknown slash commands unchanged.

- Fork a completed Codex CLI response into a new native Codex thread and session with matching retained history. Keep the original thread intact; reject in-flight, goal, image-bearing, or uncertain histories. User-message cutoffs remain unavailable for Codex because they cannot preserve Prokop's user-only cutoff on a native turn boundary.

- Add Codex CLI user-message edit and conversation revert support with upstream-history validation and durable rollback intent. A failed edit reports a bounded local reason and distinguishes preflight failure from a possibly executed rollback without exposing upstream RPC details.

- Register Prokop and Codex CLI as separate server harnesses. Session execution dispatches by persisted harness ownership, while shared session creation rules apply to HTTP and WebSocket requests.
- Reject unknown harness owners and unsupported operations without falling back to Prokop. Scheduled and learning sessions remain explicitly Prokop-owned.
- Keep the Codex CLI process, thread binding, recovery, and model catalog under its harness directory. Codex OAuth model-provider integration remains separate.
- Choose Prokop or Codex CLI models from one picker in an empty root session. The first message locks its harness; model and effort changes within the established harness remain available.
- Supply enabled workspace USER.md and MEMORY.md to Codex CLI as bounded developer instructions on thread start and resume, using the session's selected workspace root. No Codex config files are changed.
- Keep the selected workspace preconfig across Prokop and Codex CLI harnesses. Codex receives its system prompt, agent-home MEMORY.md and USER.md contents and their locations, the agent home directory, selected working root and registered additional paths, plus opted-in workspace memory as developer instructions. Codex still owns its model, tools, sandbox and approvals; missing preconfigs block turns.
- Route Codex CLI command and file-change approval requests through controller-gated asks. Command grants match the exact command and working directory for a session or workspace; file changes allow once only. Pending requests expire on interruption, process loss, or timeout.
- Show Codex command, file change, MCP, and other tool items in the conversation as persisted tool rows, updating their state from app-server item events and interrupting unfinished rows on turn exit. Render valid Codex file-change patches as line-numbered diffs instead of Markdown, with a bounded plain-text fallback for incomplete patches.
- Launch Codex turns with a process-only, trust-checked `PreToolUse` hook for shell commands and patches. Ask through Prokop for recognized sensitive or outside-workspace paths and deletions, keep native Codex escalation, and avoid a second prompt for the same approved command. Hooks do not cover every filesystem operation and may fail open on hook errors.
- Show the session auto-approval risk shield for Codex sessions and apply its current ceiling to hook asks, approving matching calls once without a persistent grant. Off, unknown risk, and critical native escalation still require manual approval.
- Send uploaded session images to Codex CLI as local image inputs, including image-only turns, and display them in the transcript. Validate attachment ownership, type, and on-disk location before starting a turn; other file attachments remain unsupported.
- Add Codex CLI native Goals with a separate token budget and live status in the composer, without changing Prokop's max-turn Goals. Keep one Codex process across goal continuations, pause before Stop, and reconcile uncertain turns against exact upstream history before accepting another message.
- Show Codex's latest reported context occupancy in the session header, with cumulative thread tokens labelled separately. Persist valid usage notifications for reloads; show an unknown window rather than inventing a percentage when Codex does not report one.
- Expose only workspace `memory` and selected-agent `agent_memory` as Codex CLI dynamic tools on new threads. Reuse the Prokop memory definitions and storage, enforce per-turn identity and current workspace settings, and route configured workspace write approvals through controller-only, once-only asks. Display memory lists as collapsed entries rather than raw Codex content-item JSON. Include Prokop's memory-use guidance in Codex developer instructions only when the corresponding tool is available.
- Show fetched pages as compact `webfetch` results instead of rendering page content and remote images in the chat. Convert HTML to Markdown by default as the tool description promises; keep the requested content available to the agent and raw-data view.
- Expose workspace-enabled `session_search` to Codex CLI using the existing Čapek executor and Prokop search host. Keep list, search, and read modes, selected-agent scope, current permission settings, and controller-only search approvals. Use Prokop-style session title lists and memory count/usage chips in Codex tool rows without rendering message or memory contents inline; preserve full results for Codex and give search guidance only when the tool is available.
- Apply the Codex session auto-approval risk ceiling to workspace memory writes and session searches. Risks above the ceiling, critical or unknown risks, and sessions with auto-approval off still require a controller-only, once-only ask.
